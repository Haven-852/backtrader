# AIquant：一套把看盘、补数、对话、策略和复盘收在同一张桌上的量化工作台

这篇文章介绍的是本仓库里正在运行的系统：AIquant，副标题是 Backtrader Agent Platform，当前版本记为 v3.0。它不是一份行情终端的说明书，也不是一篇把经典回测库重新讲一遍的教程。它要讲清楚的是：一个人在本地研究 A 股时，行情、缺口、问题、规则、纸面账户和事后复盘，怎样被放进同一套前后端里，并且让大模型在回答之前先去碰真实数据。

仓库的根仍然保留着经典 Python 回测库 Backtrader。你依然可以写一个双均线策略，喂进 Cerebro，跑一段历史。平台在这之上加了一层工作台：Vue 3 前端、FastAPI 后端、多存储引擎，以及一组大模型可以按名字调用的技能。日常研究走浏览器里的七个页面；需要纯脚本回测时，`import backtrader` 依然可用。两条线并存，互不替换。

## 一、它要解决的那件事

做短线研究的人，一天里要反复做几件彼此不连贯的事。早上要看集合竞价谁在放量、板块是不是同向；开盘后要看分时形态、判断今天的基调是能做还是只能卖；盘中要知道自己纸面上的仓位赚了还是亏了；收盘后要把当天的事实写下来，免得明天凭印象复盘；过一段时间又要把日线和分钟线整理成能训练的表，看模型到底有没有学到东西。这些事如果散落在行情软件、表格、聊天窗口和几段临时脚本里，最容易发生的不是算错一个指标，而是把“没有数据”说成“今天没有机会”，把“模型猜的价”当成“库里的收盘价”。

AIquant 的主张很具体：缺数就补数入库，有专用工具就调用工具，回答必须能指回一张表、一次工具返回或一条规则。代码写成 `600118` 时，系统按沪市补成 `600118.SH`。没有分时，就报告缺分时，不用日线收盘去冒充盘中价来做 T。训练样本只用 `train_ready = 1` 的行。自定义查询只允许只读 SQL。这些不是文案上的谨慎，而是工具手册里写死的选用顺序。

落地页用一句话概括这张桌子：把行情、补数、对话与复盘收进同一张桌面。页脚写着研究工具，不构成投资建议。这个边界要先说清楚。下面讲的选股、回测、纸面盈亏和高低点标签，都是研究流程里的中间产物，用来检验一条规则能不能被重复执行，不是下单指令。

## 二、一个人怎么走进去

未登录时先看到落地页。页首是品牌标记，中间是能力清单，技能条列出模型真正能调用的名字：SQL 工具箱、Datahubco 补数、期货主连、盘中做 T、纸面交易、市场记忆、竞价强买筛选、板块分时情绪、收盘复盘、期货 DeepView、个股尽调档案。数字区会向当前实例探测在线统计，例如库里有多少数据项、股票池有多大、训练表有多少行、技能有多少个。探测失败时，页面退回到产品能力概览，不拿一份过期数字充数。

注册之后进入工作台。第一个账号自动成为管理员。侧栏底部显示邮箱或显示名、Free 或 Pro，以及当日对话已用额度与上限。对话、行情、存储都挂在登录之后。侧栏七项与内部页签一一对应：大模型对话、行情看板、存储层状态、行情中心、策略分析、模拟交易、知识库。当前页签会记在浏览器本地，下次打开还停在离开的地方。从选股结果点一只股票，会带着代码、名称和行业跳到行情看板；看完可以回到选股器。对话页和行情页在切换时保持存活，避免来回点选就把整页拆掉、重新拉一遍数据。

技术栈按侧栏底部署的那行字来记就够：`web → routers → server → data`。浏览器里的 Vue 3、Vite 和 Tailwind 只负责呈现和操作；HTTP 由 `routers/` 分发；业务落在 `server/`，例如对话、存储预览、纸面经纪、知识复盘、选股、日内转折；取数、表结构和库连接在 `data_layer/`。大模型可调用的技能放在 `tools/`，总目录是 `tools/HANDBOOK.md`。前端技能面板和对话代理都通过 `/skills` 与这份手册对齐，避免界面上有一个按钮、模型却不知道该调哪个函数。

一次真实请求大致这样走完。浏览器把问题发到对话路由，服务层按当前保存的模型配置去调用对应厂商，并把已经勾选的技能收成函数列表交给模型。模型若决定查库或补数，执行器按函数名找到技能，参数先做校验，再进入数据层。返回值回到对话里，由模型写成中文结论，同时会话和工具轨迹写入数据库。行情看板、选股、纸面盯市走的是另一组路由，但读的是同一批表。所以对话里说“库里已有某日日线”，和看板上画出的那根 K 线，应当是同一次入库的结果。对不上的时候，以表里的行为准，而不是以句子为准。

登录和额度是这张桌子的门。未登录只能看落地页和登录框。登录后侧栏才出现。免费与专业方案的差别体现在对话等用量上限上，用了多少、上限是多少，写在侧栏底部，避免在不知情时把额度打光。研究用的行情和规则本身不靠把接口暴露到公网来完成，默认面向本机：前端、后端和数据库都在自己的机器上。这和“把策略托管到别人的云上”不是同一条路。

## 三、大模型对话：先取数，再开口

对话页是工作台的第一入口，但不是一个通用聊天窗口换了深色主题。左下角可以选择并保存自己的模型配置：DeepSeek、OpenAI、Anthropic、Grok、本机 Ollama，以及通义、智谱、Kimi 这类 OpenAI 兼容接口。厂商、模型名和密钥写入内部配置，不在存储层的表预览里展示。密钥留在本地环境或内部配置里，仓库只提交 `.env.example` 这种空模板。

会话列表保存在 PostgreSQL。刷新或浏览器把页面丢掉之后，可以回到上一次对话，而不是每次都从欢迎语重新开始。右侧技能面板列出当前注册的工具。发送一条消息时，模型按手册挑选一到两个真正需要的工具，拿到结果后再用中文下结论。函数名有固定形状：技能标识和工具标识用双下划线连接，中间的连字符改成下划线。例如日内做 T 的组合运行是 `t0_intraday__combo_run`，行情补数是 `datahubco_data__get_bars`。

手册把“不许臆造”写成操作顺序，而不是一句口号。测试某一天的高低点能不能被四套方法及其组合打中，第一步加载当天全部分钟线，第二步做命中测试，结论看组合排名，不要自己写 SQL 去近似第二步。盘中做 T 或看四法状态，走方法工具或组合运行。纸面账户的盘中盈亏，走分时末价；没有分时就说明缺失。个股、指数、ETF、板块或分钟线可能缺库时，走 Datahubco 的日线或分钟入口，分钟线先查 Redis，再查 PostgreSQL，仍缺则补数写回。全市场股票清单、训练表采集、训练表体检，各有专用入口，不靠临时拼 SQL 代替。只有在没有专用技能、又不知道表结构时，才去列出数据表、查看字段。一次调用控制在真正需要的范围里，拿到结果就停止，不再无意义地连续查库。

这种设计和“让模型更会聊天”不是一回事。它假设模型会把缺失说成确定、会把记忆里的旧价格当成今天的价格。所以平台把行情、资金、成分、竞价、复盘模板都收成可检查的函数。模型可以组织语言，不可以编造成交额和涨跌幅。

## 四、行情看板：从指数看到一只股票的 K 线

行情看板是看盘的主画面。上方可以切指数、个股、ETF。搜索一只股票，或点一只大盘指数，主图加载对应 K 线。成交量固定画在下方。其余技术指标作为子图开关，右侧在宽屏下保留一块说明区，列出当前已启用的指标。周期覆盖研究里常用的多周期视图，方便同一只标的在日线结构和更短周期之间切换。

看板下半部分是东财行业板块。板块不用一张平铺的涨跌幅表硬塞进屏幕，而是用分位疏密做成气泡：一级、二级、三级都可以点。点中之后看该板块的日 K，也可以看成分股。一级和二级支持下钻到子板块。层级关系在首次使用时会按成分股推断，所以第一次可能稍慢。没有板块数据时，可以走同步，把行业行情补进库再刷新，而不是对着空气泡猜测今天谁强谁弱。

选股器里点中的股票会带着代码跳到这块看板。研究动作因此是连贯的：先在策略页筛出观察池和推荐池，再在看板上核对 K 线、均线和所处行业，而不是把代码抄到另一个软件里重新搜索。ETF 同样有自己的标签，能看到基金类型和交易日。指数、股票、ETF、板块四类对象共用同一套图表容器，区别在数据来源和标注，不在四套互不相干的页面。

## 五、行情中心：期货主连单独放

A 股的指数和个股放在行情看板。黄金、原油、橡胶、股指等期货主连放在行情中心。这里可以看分类与合约目录、报价看板、日周月 K 线，也可以检查覆盖是不是缺了一截、日期是不是还停在更早的交易日。缺数或日期不对时，优先从数据源补日线写入 `fut_daily`，再返回报价。编造一个“大概的金价”在这个页面没有位置。

把期货从 A 股看板里拆出来，是因为合约、主连换月和报价日期的语义不一样。A 股看的是证券代码和交易日；期货主连看的是连续报价是否对齐到上一个交易日。混在一个搜索框里，很容易用股票日线的习惯去读一张期货表。行情中心把这层差异留在自己的服务里，对话侧则有对应的期货技能，读看板、查覆盖、补报价、取 K 线，和页面使用同一套补数原则。

## 六、存储层：能看见库，才能相信回答

存储层页面回答两个问题：现在哪些引擎是通的，以及某张表里到底有什么。连通性覆盖 PostgreSQL（含 TimescaleDB）、Redis、InfluxDB、MinIO，ClickHouse 作为可选的分析仓库出现在编排里。页面可以刷新。左侧选表，右侧预览，首屏大约五十行，继续滚动再加载，避免一张大表一次性灌进浏览器。

导出支持 CSV 和 Markdown，方便把一段筛选结果带到笔记或表格里。自定义表以 `u_` 开头。你可以在页面上用自然语言描述想要的表，模型生成结构并在 PostgreSQL 里建出来；也可以在对话里调用建表工具，先做一次不落库的演练，确认后再真正创建。建好的表可以列出、查询。只有自己登记过的自定义表允许删除，系统里的行情表、财务表、参照表一律拒绝删除。自定义表还可以在线增改行。系统表保持只读，是为了让模型的一次失误停在查询层，而不是改写全市场日线。

预览和导出看起来像数据库客户端的缩小版，作用却是给对话提供地面。模型说“这张表里有资金流向”的时候，人可以打开同一张表看字段和最近几行。对不上，就以表为准，而不是以句子为准。内部配置一类不该被浏览的表会从预览里藏掉，避免密钥和会话配置混进数据浏览。

数据字典按研究域组织，而不是按接口文档的顺序堆字段。基础参照包括交易日历、股票主档、更名、新股、涨跌停价、停牌。财务报表包括利润表、资产负债表、现金流量表、财务指标、业绩预告和分红。行情包括日、周、月 K 线。盘前相关包括每日指标、复权因子、集合竞价汇总。资金与交易行为包括个股资金流向、龙虎榜、融资融券汇总与明细、大宗交易。此外还有指数日线与权重、基金净值、ETF 日线、研报一致预期。时序表按交易日分区。证券代码沿用带交易所后缀的写法，主键多是代码加日期，或代码加报告期加报表类型。财务字段与上游财务接口对齐，行情的开高低收、成交量、成交额与日线接口语义一致。这样做的好处是：回测、选股和对话查询说的是同一套列名。

## 七、数据从哪里来，缺了怎么补

采集面对的是多来源、多频率、多缺口，而不是一条永远完整的实时流。环境里可以为 Tushare 配置多级 Token，也可以配置 Datahubco。日线、周线、月线、分钟线、板块、资金、财务、指数、基金、限售解禁、质押、增减持、筹码、研报、同花顺概念成分、可转债、期货主档、每日指标、复权因子、涨跌停、停牌、新股，都有对应的数据集名字。对话和页面不直接猜该调哪个远程接口，而是走数据集别名。

默认策略是：库里已经够用，就不再打远端；不够用，就拉取并写回，然后再把结果返回给调用方。也可以强制只读本地，或强制走远端但不入库。这个“先看本地、再补、再读”的顺序，保证同一次研究里后续的 SQL、看板和回测看见的是同一份已经落库的数据，而不是每次现场拉一份稍有差异的快照。

分钟线的路径更明确。单只股票的一分钟数据先看 Redis，再看 PostgreSQL 里的分钟表，仍缺则向数据源补齐并写回。批量拉取当日全部主板一分钟，是给训练准备的，不靠对每只股票各调一次分钟接口。流程是先看覆盖进度，再按批写入，最后取代码索引。单票在 Redis 里按代码和日期存放，内容包含开高低收、成交量和成交额。全市场清单单独成表 `ref_market_universe`，大约五千五百多只上市股票，带板块类型，并同步到股票主档。训练批处理从这个池子里读代码，而不是假设主档已经完整。

板块也有自己的补数粒度。某一个交易日整批东财行业涨跌和成交额缺失，按日补一批，不逐只代替。某一个板块缺一段历史、上涨家数或回测需要的市场环境，按代码和起止日期补一段。要在全部二级行业上验证规则、而多数板块都缺整段行情，则按区间做一次市场级补齐，已有较长历史的不覆盖，名称对不上的不编造。成分股缺失时取东财板块成分，并可剔除简称里带 ST 的股票以及停牌股票。停牌优先看停牌参照表，当日没有有效日线时再推断。某一个交易日整批个股资金流向缺失，按日取资金数据并写回，不传单只代码，也不编造主力净额。个股所属二级、三级行业的资金走向另有入口，依赖板块成分和板块资金表。

存储引擎的分工在设计上是清楚的。PostgreSQL 加 TimescaleDB 承担主数据、日线以上的结构化行情、财务、资金、策略与账户记录，因为研究查询需要 JOIN、窗口和事务。Redis 承担最新分时、热缓存和训练用的当日分钟快照，因为盘中要的是低延迟读取。InfluxDB 面向更高频的时序写入。MinIO 面向原始文件、公告与研报附件、Parquet 一类冷数据。ClickHouse 作为可选的大规模分析仓库。早期架构笔记里还画过消息队列、批处理集群和向量库，那是数据层的目标形态；当前工作台真正每天在用的，是上面这条“采集写入 PostgreSQL / Redis，服务层读取，模型经技能访问”的路径。写介绍时把目标和现状分开，是为了以后扩展时知道哪一层已经接通、哪一层仍是设计。

本地编排用 Docker 把这些引擎拉起来。常见宿主机端口是：PostgreSQL / Timescale `15432`，Redis `16379`，InfluxDB `8086`，MinIO `9000` 与控制台 `9001`。数据目录落在仓库下的 `data/docker/`，避免容器虚拟盘重置之后历史行情一起消失。Windows 上可以用脚本一键打开后端和前端：FastAPI 常见在本机 `8010`，Vite 在 `5173`，前端把接口代理到后端。健康检查、OpenAPI 文档，以及对话、存储、行情、策略、纸面、知识库、技能这几组路径，都挂在同一个进程上。

## 八、策略分析：从选股到回测，再写进记忆

策略页叫策略分析工作台，左侧是策略工具箱，右侧是参数、运行结果和日志。工具箱里的策略不是一份营销名单，而是后端目录里注册、前端再拉下来的条目。目前包括：双均线动量、均值回归、RSI 超买超卖、通道突破、波动率过滤、短线心得规则包、MACD 金叉死叉、布林带回归，以及趋势回踩结构止损。每条有分类、适用的市场状态、文字逻辑和可调参数。例如双均线可以改快慢周期，RSI 可以改周期和超买超卖阈值，布林带可以改窗口和标准差倍数。

趋势回踩这一条写得最接近可执行的交易假设。它要求十日均线在二十日均线之上，收盘仍在二十日均线上方，说明升势没有坏；当天低点碰到十日均线，成交量不超过前五日均量，说明是缩量回踩而不是放量砸破；收盘相对近十日结构低点的风险不超过百分之四。信号在收盘确认，次日开盘买入。开盘相对信号日收盘高开超过百分之一，就放弃追价。A 股 T+1 被写进规则：进场当天不能卖，止损最早从进场后的第二个交易日开始。浮盈达到两倍初始风险之后，止损上移到持仓期最高价减去二点五倍前一日 ATR。收盘跌破十日均线并且放量超过前五日均量的一点五倍，次日开盘离场；否则最多持有五个交易日，再按收盘近似卖出。同一标的同时只持一笔。滑点以基点计，默认五个基点。这条策略自己也写明：回测不含佣金、印花税、涨跌停无法成交和停牌，只作参考。赚钱的设想是小亏快砍、趋势延续时吃一段，不是去猜涨停。

选股器和回测挨在一起，但不是同一个动作。选股面向“今天收盘之后，哪些票进入观察、哪些票值得推荐、哪些票符合回踩结构”。规则大致是：A 档观察池按得分筛，达到阈值后进入自选观察，不直接当成买入；B 档按得分给出推荐；C 档就是上面的缩量回踩，收盘出信号、次日开盘才是买点，止损看结构低点。窗口大约四十个交易日。缺日线时先走 Datahubco 把窗口补齐，再计算，避免半截样本被当成“没有信号”。一键推荐流水线走的是观察池到起飞推荐，不把 C 档回踩混进同一条自动链。点结果中的一行，跳到行情看板看 K 线。

回测使用库里的真实日线，而不是随机生成的价格。工作台有两种节奏：一种是逐步执行，假设、运行、反思、写入记忆分开走；另一种是一键按循环跑完。回测开关从后端加载，其中包括防止用到未来数据的回溯保护，以及走样本外的滚动验证。关掉回溯保护意味着允许同一天收盘价成交，日志会明确标出前视风险，而不是悄悄变成更好看的收益。结果返回累计收益，并尽量带上 K 线、买卖点和本金曲线。没有日期序列或没有 K 线时，页面说明缺什么，而不是画一张空图假装已经验证。

策略记忆把一次回测的结论留下来。市场状态变化时，代理可以根据状态在目录里换一条更匹配的策略，例如趋势和震荡不共用同一套默认逻辑。短线心得规则包则把笔记里的约束收成可调参数，例如隔夜浮盈减掉一半左右、最长持有天数。笔记本身还在知识库和 `doc/guidelines/` 里，策略目录只是把其中能参数化的部分放进回测。两者不要混成“笔记已经等于实盘成绩”。

## 九、盘中能力：竞价、板块情绪、做 T 和转折点

短线笔记里把一天拆成几件必须分开的事：识别今天的基调，在集合竞价里找放量的股票和板块，在分时里找结构低点而不是事后最低价，以及用区间而不是一个精确价格去想次日的高低。系统里已经有对应的技能，缺的是把它们串成纪律，而不是再写一套平行的指标。

盘前九点二十到九点二十五，主板竞价强买筛选的股票池来自昨日强势与涨停池的并集。竞价成交额处于高分位并且价格在抬升，才进入推荐，并附上近三日和规则原因。这里的“强买”是量能代理，不是逐笔委托的买卖方向。若返回不完整，并指出还要补竞价分钟和涨停榜，就先补再跑，不能在覆盖不足时宣布今天没有热点。

开盘后看东财二级行业的分时情绪。先按日线涨跌幅的绝对值取靠前的板块，再用成分股分时等权合成，输出近三日和一段情绪说明。缺日线、缺成分或缺分时，工具会点名下一步该调用的补数动作。板块基调要和指数、个股形态一起看：指数是高开低走还是低开高走，领涨板块是否站上均价，个股是否落在允许跟随的形态里。笔记里的原则是，上午十点以前若基调偏空，当天的强势跟随就停，只处理卖出。十点四十到下午两点四十偏“只卖不买”。这些时间纪律写在研究笔记里，技能负责提供事实，人不该用一次工具调用代替整段纪律。

日内做 T 使用一分钟分时，数据表是分钟线库。没有分时就停止，不许捏造。盘中分析必须按当前时点截断，禁止把收盘后的当日最高最低当成当时已经知道的特征。四套方法可以单独看，也可以组合后对照真实高低打分。方法 A 看回撤和剩余时间，方法 B 看冲击是否衰竭，方法 C 是同时点的放量倍数，不单独下单，方法 D 区分孤立放量和连续放量。组合测试默认跑全部组合，排名看哪一组在容差内打中高低。成交纪律是信号那一分钟的收盘价成交，十四点五十五分强制了结。全市场还可以先用测试日之前的日线把股票分成上升、下跌、横盘，再测当天的组合，避免用事后才知道的趋势去解释当天的信号。

另一条模型线和做 T 的规则线分开。工作台里的日内转折，把一分钟重采样成五分钟，用 LightGBM 做三分类：未来大约三根五分钟 K 线里，价格先碰到上方障碍、先碰到下方障碍，还是中性。障碍用 ATR 的一部分来定。特征只用当前及更早的价格和指数、板块上下文。样本不够时返回需要更多数据，而不是勉强给一个方向。这条模型适合当过滤器：规则已经给出买点时，若模型明显偏向先下，就放弃。它不负责报出一个最高价或最低价。

日频训练表负责另一件事。每一行是某只股票在某个交易日收盘后能够观测到的特征。标签 `y_high` 和 `y_low` 是次日最高、最低相对当日收盘的收益，不是当天已经走完的振幅。最后一天没有次日，标签留空，并且 `train_ready` 为 0。绝对价格不进特征。训练按交易日切分，禁止打乱之后随机划分，否则同一段行情会同时出现在训练和测试里，成绩会好看但没有意义。板块类型、交易时段形态（正常、一字涨停、一字跌停、平盘一字、停牌）作为类别信息保留，停牌行用占位把序列补连续，而不是删掉造成时间空洞。

采集这条表有环境检查：内存、磁盘、数据库和表要先就绪。可以单票从较早的日期补全并在表内做截面抛光，也可以按股票池分批写入，每批成功后再在本地重算截面、广播和可训练标记。体检工具先给出问题目录，再全表计数，最后按顺序修复：改成次日标签、补截面、标记一字和停牌、插入停牌占位、重打可训练标记。截面回写的量很大，不走只读 SQL 工具，而走专门的分批回写，对话里限制批次数，全量则用脚本跑，以免一次对话把库拖死。

两条线必须分开记。五分钟三分类回答的是“接下来一小段更可能先上还是先下”。日频双回归回答的是“相对今天收盘，明天的高点和低点大致在什么幅度”。笔记里的用法是把后者当成区间：上沿参考昨日高点、ATR 和涨停价中较近的约束，下沿参考昨日低点、ATR 和开盘缺口，用来放止损和止盈。选谁，仍然看板块和个股规则，不看一个点预测。

## 十、模拟交易：把规则放进一个不会伤到本金的账户

模拟交易页是纸面账户，不是券商柜台。左侧可以开户、改名、切换和删除。删除会同时清掉该账户的持仓、委托、成交和决策日志，所以操作前有确认。账户显示持仓只数和当天唤醒次数。没有账户时，交易对话会要求先开户。

盯市优先用一分钟分时的最后一笔价格。没有分时时，净值改用上一交易日收盘价，避免账户因为缺分钟线就只剩现金、看起来像已经清仓。这个收盘价只用于记账，不用于做 T 决策。做 T 仍然以分时为准。页面上可以看持仓、触发一次分时做 T 扫描，或跑“日课”：日切、风控和当前时点的做 T 放在同一次动作里。定时器可以打开：非交易时段的晚上做选股，交易日盘中按大约五分钟的间隔扫描做 T。决策过程留在日志里，方便事后看模型或规则当时依据了什么，而不是只留下一条成交。

告警和自动交易分开。可以开启盘中扫描，默认只推送、不卖出。阈值能保存。推送渠道包括企业微信和 PushPlus 一类外部通知，配置在环境变量里，不写进代码。另一块是自选监控池，和虚拟持仓无关：把现实里关心的代码放进去，触发后按既定结构生成简报，同时推到外部渠道。这样，纸面账户负责检验规则的盈亏路径，监控池负责提醒真实关注的股票，两者不要合成一个“系统已经替你下了单”的印象。

交易对话挂在当前账户上。可以说感知某只股票并决定是否建仓，代理读取行情和账户状态后再回答。T+1 在纸面层同样生效，当天买入不能当天卖出。滚动到下一交易日、列出账户、读取持仓，都有对应技能，因此对话里的“卖出”若违反交易制度，会被规则挡住，而不是只在文字上答应你。

纸面层的价值是把笔记里的时间纪律变成可回放的动作。晚上选出的名单、次日竞价是否还强、十点四十之前有没有买点、中间时段是否只卖、尾盘超跌是否只允许小仓并且要等次日竞价确认，都可以在账户日志里留下痕迹。一次好看的净值不能代替这些痕迹。没有痕迹的盈利，下次无法知道是规则对了还是行情刚好配合。

## 十一、知识库：让复盘离开聊天窗口

知识库分成四块：市场记忆、交易规则、外部知识、实验室。市场记忆承接“今天发生了什么”。有一条技能专门生成当日市场记忆草稿，草稿不等于已经写入知识库，必须经过人的确认。这样可以避免模型把一段流畅的收盘总结直接变成日后被引用的事实。

交易规则存放可以反复执行的约束。短线笔记里的例子包括：中间时段只卖不买，隔夜只埋伏当天已经走强的方向，不隔夜硬扛高潮龙头，也不隔夜埋伏当天大幅杀跌的标的。规则页的作用是把这类句子从聊天记录里摘出来，变成以后选股和纸面循环可以对照的条目。规则改了，就改这里，而不是在某次对话里口头改口。

外部知识用来收方法、文章和他人的框架，例如形态与资金、分时盘口、全球市场之间的联动。仓库的 `doc/guidelines/` 里已经有一批这样的笔记：多维度思考、投资周期与选时、全球市场逻辑、分时形态、短线心得，以及 LightGBM 高低点训练方案。知识库页面是这些材料进入日常检索的地方，文档目录则保留更长的原文。引用时应能回到出处，避免把外部方法说成自己的回测结论。

实验室存放还没成为规则的实验：一次参数对比、一次特征清洗、一次失败的过滤。实验失败和实验成功一样值得留下。策略记忆偏“这次回测我相信什么”，实验室偏“这次尝试的条件和结果是什么”。混在一起，以后会分不清哪条已经允许进纸面账户，哪条还只是一次试验。

收盘复盘还有一条独立技能。它读取复盘工作流、模板和接口映射，按日期和关注点拼出任务提示，最后校验成稿是否具备应有的章节。上游数据可以来自本平台已经入库的行情、资金和龙虎榜，并在文中标注来源。个股尽调是另一条流水线：给定代码，按档案指南组织基本面、质押、解禁、减持等风险，而不是用一段行情描述代替尽调。期货侧的 DeepView 技能面向席位、基差与期限结构、仓单库存和跨期，和 A 股复盘分开，避免用股票语言去写一张期货研报。

## 十二、一条交易日里，这些页面怎么接上

把上面的模块按时间放回一天，系统的形状会更清楚。

盘前，先看存储和覆盖是否正常，再跑主板竞价筛选。返回若提示缺竞价分钟或涨停榜，先补数。同时看二级行业日线，确认昨天的强势板块今天竞价是否还在。竞价结果是确认开关：弱开、板块集体走软，隔夜仓按事先写好的规则处理，而不是在九点二十五重新发明一条策略。

开盘后的大约半小时用来定基调。指数分时相对昨收和均价，板块分时是否同向，个股是否属于允许跟随的形态。基调偏空，强势跟随策略当天不再开新仓。十点四十之前，若板块仍强、个股形态允许、价格在均价之上或刚刚收回，才讨论买点。买点出现时，可以用五分钟转折模型看它是否明显偏向先下。纸面账户若要执行，按分时价格记账，并遵守 T+1。

中间时段以卖出和持有检查为主。做 T 的四法只使用截至该分钟的价量。十四点二十左右若要看超跌反弹，扫描结果只进入观察，仓位必须小，而且要等到尾盘不再加速下跌、次日竞价仍能确认，才谈隔夜。这是笔记里的约束，系统提供扫描和账户，不把“跌幅榜第一名”自动变成买单。

收盘后，把日线选股再跑一次：观察池、推荐池、回踩信号分开看。回踩信号留给次日开盘，高开过多就放弃。然后生成市场记忆草稿，人确认后再入库。需要复盘长文时走复盘技能，需要单只股票的风险档案时走尽调技能。策略若有变更，跑回测时保持回溯保护打开，再决定是否写入策略记忆。训练数据若要更新，按股票池分批采集，体检通过后才让新行进入 `train_ready = 1`。

这一天里，人做的是判断和确认，系统做的是取数、留痕、限制前视和拒绝编造。顺序反了，工作台就会退化成一个更会说话的行情软件。

## 十三、它故意不做什么

系统不保证收益。回测文字里已经写明费用、涨跌停和停牌没有完全进入成交模型。纸面账户没有真实滑点的全部形态，通知推送也不是成交回报。任何页面上的推荐、得分和模型分类，都要和原始 K 线、成分和资金表对得上，才可以进入下一次讨论。

系统不把经典 Backtrader 换成一个只能在网页上点的黑盒。仓库仍保留原引擎和安装脚本，GPL v3 的许可也留在根目录。需要在脚本里做信号研究和经纪商仿真时，继续用 Cerebro。需要在多个人、多天的研究里共享数据、会话和规则时，用这套工作台。两者读到的日线若来自同一张 PostgreSQL 表，比较才有意义。

系统不让模型直接改系统表，不让只读 SQL 工具去做千万行回写，不让一次对话拉完整全市场分钟线进内存。这些限制看起来像功能缺失，实际上是把故障挡在可恢复的位置：批处理可以续跑，自定义表可以删除，系统表不能被一次提示词清空。

系统也不把设计文档里的每一层都说成已经上线。消息队列、全量数据湖治理、向量检索，是数据架构笔记里的后续阶段。介绍当前系统时，以页面、路由、服务和技能手册为准。手册更新的方式也写在手册末尾：新工具放进 `tools/`，补上章节，在注册表里登记，并在路由与执行器里增加分发。少任何一步，界面和模型就会各说各话。

## 十四、适合谁，以及怎样开始

这套系统适合已经有自己的交易笔记、希望把笔记变成可重复步骤的人。你需要愿意维护本地的数据库和数据源密钥，愿意在模型回答之前看一眼它调用了什么，也愿意把“没有数据”当成一种结果。它不适合想打开软件就得到一键实盘的人，也不适合把对话里的涨跌幅直接贴进委托单的人。

开始的路径不长。复制环境模板，填上模型密钥和数据源密钥，用编排文件启动数据库和缓存，再执行一键启动脚本。浏览器打开本地前端，注册第一个管理员账号，先在存储页确认 PostgreSQL 是通的，再在对话里按手册问一个必须查库才能回答的问题，例如某只股票最近若干日的收盘是否在库里。能看见工具返回的行，再去看行情看板和选股。训练、纸面定时器和外部推送可以后开。顺序反过来，很容易把空库上的模型想象当成系统能力。

若只记三句话，可以记这三句。第一，同一张桌子上完成看盘、补数、回测、纸面和复盘，数据以入库结果为准。第二，大模型负责组织问题和调用工具，不负责发明价格。第三，规则、实验和市场记忆要写进知识库，否则第二天的你只剩一段聊天记录。

AIquant 的名字把 AI 和量化放在一起，真正合在一起的方式不是让模型预测明天的收盘价，而是让每一次预测、每一次筛选、每一次纸面成交都能指回当时看得见的数据。做得到这一点，这套系统就完成了它对自己的定义：一个本地的量化智能体工作台。做不到这一点，它就只是又一个深色界面的聊天窗口。区别不在口号，而在你下一次提问时，它有没有先去查那张表。
